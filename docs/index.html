A curated hub and benchmark framework for thermal-fluid models across servers, racks, CDUs, and facility cooling systems.

Why this benchmark matters

Cooling models often cannot be compared because their heat paths, coolant conditions, time bases, and reported outputs differ. This project creates a shared, auditable path from documented measurements to comparable model runs. It does not present an energy-balance calculation as model validation.

1. COMMON CONTRACT

Comparable inputs and outputs

Each model declares its control volume, input trace, initial state, units, time step, output definition, and run record.

2. MEASURED EVIDENCE

RDHx circuit telemetry

The first intake uses source-reported PLC temperature, flow, and control signals alongside node telemetry from the M100 monitoring record.

3. HONEST VALIDATION

Chronological holdouts

Models will be assessed on future contiguous intervals, not randomly mixed neighboring 20-second records.

Measured-system scope

The current case is an RDHx liquid-circuit benchmark. The data record supports a measured intake and signal-consistency audit now. It does not yet document an individual-rack liquid branch or a cold-plate heat path.

  • Measured: node electrical power and inlet-air temperature; PLC flow, supply/return temperature, and controller signals.
  • Derived locally: direct temperature rise and a screening heat-rate diagnostic.
  • Required before model-to-rack claims: panel-to-rack topology, loop interpretation, and source permission for publishing derivatives.
Evidence status
Local M100 analysis outputs are not deployed here. The public repository carries the code, schemas, source links, and synthetic tests; third-party raw data and derived figures remain outside the release until rights are confirmed.

What model developers receive

A developer supplies a runnable implementation and a machine-readable run record. The framework checks the record, applies common inputs and holdout windows, and compares declared outputs against measured targets when the system boundary matches.

Who benefits

Researchers can compare reduced-order, network, and simulation models. Operators can see which measurements constrain a prediction. Tool users can identify where a claimed result is supported, proposed, or blocked by missing facility metadata.

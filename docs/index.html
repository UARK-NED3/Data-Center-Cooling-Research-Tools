Why this benchmark matters

The repository is a discovery hub for cooling tools and data across component, rack, room, and facility scales. The benchmark adds the shared physical and reporting contract that a selected model and dataset must satisfy before their results are compared. It does not present an energy-balance calculation as model validation.

1. COMMON CONTRACT

Comparable inputs and outputs

Each model declares its control volume, input trace, initial state, units, time step, output definition, and run record.

2. SYNTHETIC MODEL TESTS

Declared disturbances

The v1.1 suite compares a quasi-steady balance, a two-node thermal network, and a parallel-branch thermal-hydraulic model under declared synthetic inputs.

3. HONEST CLAIMS

Evidence-gated results

Verification, conditional diagnosis, and empirical validation have different prerequisites and must not be conflated.

Current benchmark scope

The public v1.1 case is a synthetic rack-manifold technology-cooling-system benchmark. It compares declared model structures without presenting an assumed heat path as an empirical validation case.

  • Implemented: M1 quasi-steady balance, M2 two-node reduced-order response, and M3 parallel-branch thermal-hydraulic network.
  • Generated: traceable synthetic time series, conservation residuals, and vector figures.
  • Required before hardware-accuracy claims: documented topology, sensor locations, uncertainty, and a measurement-aligned model run.
Evidence status
The public repository carries NED3-authored synthetic cases, schemas, source links, and tests. M3 is implemented in Python; a separate Simscape adapter remains unexecuted. Third-party raw data and derived figures remain outside the release until rights are confirmed.

What model developers receive

A developer supplies a runnable implementation and a machine-readable run record. The framework checks the record, applies common synthetic inputs, and compares compatible outputs. Measured targets are added only when the system boundary and evidence are documented.

Who benefits

Researchers can compare reduced-order, network, and simulation models. Operators can see which measurements constrain a prediction. Tool users can identify where a claimed result is supported, proposed, or blocked by missing facility metadata.

Maintained by the NED3 Laboratory, University of Arkansas. Source code and benchmark documentation are available in the linked GitHub repository.
